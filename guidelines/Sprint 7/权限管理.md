1. 目标

以最低实现成本明确 ATLAS 的系统管理、数据查看、团队协作、TFL 编辑、Copilot 和 Dashboard 权限，并确保后续增加 Unit Lead、Runtime、QC Programmer 等能力时无需更换权限架构。

2. 权限模型
登录账号仅支持 SSO 账号，不建设本地账号。
固定系统角色仅保留 Admin。
业务权限由对象关系决定：Study Owner、Event Owner、Event Team Member、Output Assignee。
TFL Page Occupant 仅用于防止多人同时编辑，不属于业务角色。
同一用户拥有多种关系时，权限取并集；无匹配权限时默认拒绝。
所有页面、Copilot 和下载接口均由服务端鉴权，不依赖前端隐藏按钮。
Admin 和权限关系通过版本化配置及业务数据维护；首期不建设角色权限配置页面，不支持账号级 Allow/Deny 例外。
3. 权限规则
ID	操作或数据	允许主体	规则
PERM-01	创建、维护 Project 和 创建Study	Admin	在独立管理页面完成ATLAS-573；创建 Study 时必须指定唯一 Study Owner。
PERM-02	维护Study（包括转移 Study Owner）	Admin、当前 Study Owner	可转给任意有效账号，转移后仍保持唯一。
PERM-03	创建 Event	Study Owner	创建时指定唯一 Event Owner，可指定自己或他人。
PERM-04	维护 Event 基本信息	Event Owner	Study Owner 不因上级身份自动获得维护权限。
PERM-05	转移 Event Owner	Study Owner、当前 Event Owner	可转给任意有效账号，新 Event Owner 自动加入 Event Team。
PERM-06	删除误创建 Event	Event Owner	必须先终止运行中的 Agent，成功后才能删除。首期不提供归档。
PERM-07	查看 Event	任意已登录用户	可查看全部 Event 的基本信息、Shell 和最后已保存 Code。
PERM-08	下载或导出 Event 内容	Event Team Member	按目标 Event 校验；非 Team Member 不允许下载或调用导出接口。
PERM-09	添加 Event Team Member	任意 Event Team Member	可添加任意有效账号，无审批。
PERM-10	移除 Event Team Member	Event Owner	Event Owner 不能移除自己，必须先转移 Owner。
PERM-11	单个或批量分配 TFL	Event Owner	在现有独立页面将 TFL 分配或重新分配给本 Event Team Member/或添加event team member+分配同时完成。
PERM-12	自助接手 Output	Event Team Member	目标 TFL 无有效页面占用时，可执行 Assign to me。
PERM-13	人工编辑和保存 Output	当前 Output Assignee	Assignee 进入页面后直接编辑，不增加申请锁动作。
PERM-14	查看 Event/TFL Copilot 会话	Event Team Member	可查看本 Event 下全部会话；会话不按个人隔离。
PERM-15	向 Event Copilot 发送消息	Event Team Member	可要求 Event Copilot 处理本 Event 下任意 TFL。
PERM-16	直接向 TFL Copilot 发送消息	当前 Output Assignee	非 Assignee 只能通过 Event Copilot 间接触达该 TFL。
PERM-17	接受或拒绝 Code Patch	目标 Output 当前 Assignee	可逐个处理或 Accept All；接受后才写入 Code。
PERM-18	查看 Event Dashboard	Event Owner	仅查看当前 Event 范围。
PERM-19	查看 Study Dashboard	Study Owner	仅查看当前 Study 范围。
PERM-20	查看和导出全局 Dashboard 报告	Admin	按 Unit 汇总其下 Study 的 Token 消耗等数据。
PERM-21	选择 Reference	Study Owner、Event Team Member	Reference 全局可选；首期不提供新增、修改、停用等维护功能。
PERM-22	Runtime	首期无人	不显示入口且服务端默认拒绝，待后续接入。

补充边界：Project 仅用于 Study 分组，不作为数据可见性边界；Study Owner 不自动加入其下 Event Team；Event Owner 必须是 Event Team Member；Admin 不自动获得 Event Team 的下载或 Copilot 权限。

在线查看 Code 后的浏览器复制不单独控制；文件下载、批量导出和导出接口统一按下载权限控制。

Study Owner 和 Event Owner 均唯一。
Study Owner 失效时由 Admin 更换；Event Owner 失效时由 Study Owner 更换。
Event Owner 是初始 Team Member；之后任意 Team Member 均可添加成员。
成员被移除后立即失去下载、Copilot 和接手 Output 的权限；其负责的 Output 自动变为 Unassigned，其页面占用同时失效。
账号失效后，所有新请求立即被拒绝。
一个 Output 同时最多有一个 Assignee，也可以处于 Unassigned 状态。
Event Owner 可在已有分配页面进行单个或批量分配；普通 Team Member 只能执行 Assign to me，不能指派他人。
分配、重新分配和自助接手前，服务端必须检查目标 TFL 是否存在有效页面占用。




4. 审计要求（可Sprint 8再做）

系统需记录 Owner 转移、Team 添加/移除、Assignee 单个/批量变化、页面占用强制释放、Patch 生成/接受/拒绝、Event 删除、Event 内容下载/导出、全局报告生成/导出。

每条记录至少包含操作者、目标对象、变更前后、操作时间和结果。首期不建设独立审计页面，由运维按需查询；普通页面查看和心跳不记录业务审计。

5. 待确认规则（TBD）

- **Event 初始 Owner**：首期 Demo 暂定由创建 Event 的 Study Owner 自动成为初始 Event Owner，Create Event 表单不增加 Owner 字段。该规则与 PERM-03 中“创建时指定唯一 Event Owner”的表述存在差异，待正式 PRD 确认后统一。
- **Event Owner 转移后的旧 Owner**：暂定新 Owner 自动加入 Event Team，旧 Owner 保留为普通 Event Team Member，以避免权限突然丢失或其负责的 Output 自动变为 Unassigned。是否自动保留待确认。
- **Disabled Project / Study 对已有 Event 的影响**：已明确不可创建新 Event，但是否仍允许转移 Event Owner、维护 Team、分配 Output、使用 Copilot、下载、编辑和删除 Event 待确认。
- **Event Owner 账号失效后的 UI 与运行状态**：由 Study Owner 更换的权限已明确；失效标记、提醒方式，以及更换前是否限制编辑、下载或 Copilot 待确认。

6. 已确认的页面口径

- Events 页 Owner 列：所属 Study 的 Study Owner和当前 Event Owner 可直接转移 Owner；其他用户只读。Team Members 页面保留相同的 Owner 转移能力。
- `My Events`：仅包含当前用户作为 Event Team Member 参与的 Event；Event Owner 因必须属于 Event Team，因此也包含在内。Study Owner、Event 创建者或 Output Assignee 身份本身不额外扩大筛选范围。
