## 1. 使用范围

本页优先定义 Atlas 的系统管理、数据查看、团队协作、TFL 编辑、Copilot、Dashboard、Reference、Runtime 权限。

本页不展开具体 UI 方案；多人编辑的断网恢复、冲突保存等细节，放在 [多人共同编辑](https://app.notion.com/p/3cdee95b51ec8169a8dbe4157cc623d0?pvs=21) 中继续讨论。Event 删除规则放在 [Event删除：Event增加删除功能](https://app.notion.com/p/Event-Event-5d4e61c57f5f44dabf45817926d6f787?pvs=21) 中维护。

## 2. 核心原则

| 原则 | 当前规则 |
| --- | --- |
| 最小系统角色 | 固定系统角色仅保留 Admin |
| 权限由对象关系决定 | 业务权限由用户与对象的关系决定，包括 Study Owner、Event Owner、Event Team Member、Output Assignee |
| Page Occupant 不是业务角色 | TFL Page Occupant 仅用于防止多人同时编辑，不属于业务角色 |
| 权限取并集 | 同一用户拥有多种关系时，权限取并集 |
| 默认拒绝 | 无匹配权限时默认拒绝 |
| 服务端鉴权 | 所有页面、Copilot、下载接口和导出接口均由服务端鉴权，不依赖前端隐藏按钮 |
| 首期不做权限配置页 | Admin 和权限关系通过版本化配置及业务数据维护；首期不建设角色权限配置页面 |
| 首期不支持账号级例外 | 不支持账号级 Allow / Deny 例外 |
| 查看与导出分离 | 在线查看 Code 后的浏览器复制不单独控制；文件下载、批量导出和导出接口统一按下载权限控制 |

## 3. 权限关系模型

| 权限关系 | 说明 | 主要影响 |
| --- | --- | --- |
| Admin | 系统管理关系；主要使用 Project 管理页面 | 创建 / 维护 Project，创建 Study，查看和导出全局 Dashboard 报告 |
| Study Owner | 某个 Study 的唯一负责人 | 维护 Study、转移 Study Owner、创建 Event、指定 / 转移 Event Owner、查看 Study Dashboard |
| Event Owner | 某个 Event 的唯一负责人，且必须是 Event Team Member | 维护 Event 基本信息、转移 Event Owner、移除 Team Member、分配 / 重新分配 TFL、删除误创建 Event、查看 Event Dashboard |
| Event Team Member | 某个 Event 的团队成员 | 下载 / 导出 Event 内容、查看 Event/TFL Copilot 会话、向 Event Copilot 发消息、添加 Team Member、在无有效页面占用时 Assign to me |
| Output Assignee | 某个 TFL / Output 当前负责人；一个 Output 同时最多一个 Assignee，也可处于 Unassigned 状态 | 人工编辑和保存 Output、直接向 TFL Copilot 发消息、接受 / 拒绝 Code Patch |
| TFL Page Occupant | 当前占用 TFL 页面的人；技术锁状态，不是业务关系 | 防止多人同时编辑；控制当前页面是否可写 |
| Logged-in User | 任意已登录 SSO 用户 | 查看全部 Event 的基本信息、Shell、最后已保存 Code |

## 4. 关键边界

| 边界 | 当前规则 |
| --- | --- |
| Project 不作为数据可见性边界 | Project 仅用于 Study 分组，不作为数据可见性边界 |
| Project 没有 Owner 概念 | 当前不设 Project Owner；Project 管理主要由 Admin 完成 |
| Admin 不自动获得业务协作权限 | Admin 不自动获得 Event Team 的下载、Copilot、Assign to me 或 TFL 写权限 |
| Admin 的 Study 范围受授权限制 | Project 管理页面主要给 Admin 用，但 Admin 只能访问被授权的 Study |
| Study Owner 不自动加入 Event Team | Study Owner 不因上级身份自动获得 Event Team 权限 |
| Event Owner 必须是 Event Team Member | 新 Event Owner 自动加入 Event Team |
| 账号失效立即拒绝新请求 | 账号失效后，所有新请求立即被拒绝 |
| 成员移除立即失权 | 成员被移除后立即失去下载、Copilot 和接手 Output 的权限 |
| 被移除成员的 Output 自动 Unassigned | 成员被移除后，其负责的 Output 自动变为 Unassigned，其页面占用同时失效 |

### 5.5 TFL / Output 编辑与分配

| ID | 操作或数据 | 允许主体 | 规则 |
| --- | --- | --- | --- |
| PERM-11 | 单个或批量分配 TFL | Event Owner | 在现有独立页面将 TFL 分配或重新分配给本 Event Team Member；也可添加 Event Team Member + 分配同时完成 |
| PERM-12 | 自助接手 Output | Event Team Member | 目标 TFL 无有效页面占用时，可执行 Assign to me |
| PERM-13 | 人工编辑和保存 Output | 当前 Output Assignee | Assignee 进入页面后直接编辑，不增加申请锁动作 |
| PERM-17 | 接受或拒绝 Code Patch | 目标 Output 当前 Assignee | 可逐个处理或 Accept All；接受后才写入 Code |

补充规则：

- 普通 Team Member 只能执行 Assign to me，不能指派他人。
- 分配、重新分配和自助接手前，服务端必须检查目标 TFL 是否存在有效页面占用。
- 一个 Output 同时最多有一个 Assignee，也可以处于 Unassigned 状态。
- TFL Page Occupant 仅用于防止多人同时编辑，不属于业务角色。
- 断网恢复、心跳释放、旧页面保存冲突等极端场景在 [多人共同编辑](https://app.notion.com/p/3cdee95b51ec8169a8dbe4157cc623d0?pvs=21) 中维护。

### 5.6 Copilot

| ID | 操作或数据 | 允许主体 | 规则 |
| --- | --- | --- | --- |
| PERM-14 | 查看 Event / TFL Copilot 会话 | Event Team Member | 可查看本 Event 下全部会话；会话不按个人隔离 |
| PERM-15 | 向 Event Copilot 发送消息 | Event Team Member | 可要求 Event Copilot 处理本 Event 下任意 TFL |
| PERM-16 | 直接向 TFL Copilot 发送消息 | 当前 Output Assignee | 非 Assignee 只能通过 Event Copilot 间接触达该 TFL |

补充规则：

- Copilot 不产生额外权限。
- Copilot 代表当前用户执行操作。
- 任何保存、应用、落库修改必须遵守当前用户对目标 TFL / Output 的权限。
- 接受 Code Patch 后才写入 Code。

## 6. 审计要求

审计可 Sprint 8 再做。首期不建设独立审计页面，由运维按需查询；普通页面查看和心跳不记录业务审计。

### 6.1 需要记录的操作

| 操作类型 | 是否记录 | 状态 |
| --- | --- | --- |
| Owner 转移 | 需要记录 | 🟡 |
| Team 添加 / 移除 | 需要记录 | 🟡 |
| Assignee 单个 / 批量变化 | 需要记录 | 🟡 |
| 页面占用强制释放 | 需要记录 | 🟡 |
| Patch 生成 / 接受 / 拒绝 | 需要记录 | 🟡 |
| Event 删除 | 需要记录 | 🟡 |
| Event 内容下载 / 导出 | 需要记录 | 🟡 |
| 全局报告生成 / 导出 | 需要记录 | 🟡 |
| 普通页面查看 | 不记录业务审计 | ✅ |
| 心跳 | 不记录业务审计 | ✅ |

### 6.2 单条审计记录字段

| 字段 | 说明 | 状态 |
| --- | --- | --- |
