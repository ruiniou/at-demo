# Dropdown & Select 交互规范 (Interaction Rules)

本文档记录了基于 B2B 高密度数据表单及复杂工具栏场景下的下拉组件交互准则。

## 核心原则：功能性标识 大于 装饰性动画 (Function over Decoration)

在绝大多数 C 端应用中，下拉组件往往通过小箭头（Chevron）的上下翻转来指示菜单的展开与收起。然而，在我们所处的**临床数据高密度录入场景**与**复杂视图工具栏**中，该设计会引入过多的视觉噪音（Visual Noise）。

因此，本系统采用以下“反动画”但更加清晰直观的交互规则：

### 1. 禁用箭头翻转动画
* **规则**：全局所有的 `Select`、`MultiSelect`、`Dropdown` 以及带有下拉选项的小标签，**一律禁止**在其内部使用箭头旋转动画（如 `rotate-180`）。
* **原因**：
  * 在密集的表单页中，用户频繁 Tab 切换或快速操作时，满屏跳动的箭头会极大地干扰视线。
  * 箭头（`▼`）仅仅作为组件的**“身份标识（Signifier）”**，告知用户这是一个下拉触发器，而不是当前状态的指示器。

### 2. 强化触发器 (Trigger) 的高亮反馈
既然禁用了箭头的状态指示，我们必须通过触发器自身的视觉变化来反馈“展开 (Active/Focus)”状态。

* **对于表单级组件 (Form Selects)**：
  * 当下拉菜单展开时，输入框主体必须呈现明确的 `Focus` 状态。
  * **样式标准**：使用品牌色边框与外发光（例如：`border-brand-1 shadow-[0px_0px_0px_2px_var(--color-az-secondary)]`）。
* **对于工具栏 / 悬浮小标签 (Toolbars / Utility Dropdowns)**：
  * 当下拉菜单展开时，触发器按钮本身必须保持持续的 `Active / Hover` 状态。
  * **样式标准**：通过加深底色或边框（如 macOS 工具栏的选中状态），使得弹出的浮层在视觉上和按钮主体强关联。

### 总结 Checklist
- [x] 代码中是否存在因展开下拉而触发的 `rotate-180` 动画？（必须移除）
- [x] 下拉展开时，组件本身是否具有明显的焦点高亮或 Active 底色？（必须添加）
