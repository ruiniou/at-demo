# Demo Log 模块结构化改造

## 背景
当前 Demo 的 Log 区域只有假记录（占位文本），没有结构化字段。本次改造目标：参照 SAS Server 原生日志模块的真实结构，把 Log 区域改造成结构化展示，为后续 Figure 模块的 Runtime 审核体验（log + RTF 对照 Shell）打基础。

**这是 Demo 层面的展示改造，不涉及真实日志解析逻辑的实现**——数据继续用 Mock，但数据结构和展示形式要贴近真实。

## 参照结构（来自 SAS Server 日志模块截图）

### 1. 顶部状态计数条
一行展示三类日志的计数，各自带图标，组件用4px圆角的按钮Tab：
-  错误 (N)
-  警告 (N)
- ℹ️注意 (N)



### 2. 结构化错误列表（表格）
选中错误时，展示 ERROR 级别的条目。其他类型的信息也仅显示在选中该类型时

表格字段：
| 字段名 | 说明 |
|---|---|
| 说明 | 报错的具体描述文本，如 "ERROR 388-185: 期望算术运算符。" |
| 行 | 报错在原始日志文本中的行号 |
| 受影响的代码 | 报错对应的代码片段摘要 |
| 日志行 | 日志文本对应的行号定位 |
| 程序行 | 对应到用户代码编辑器中的实际代码行号 |

表格每一行可点击，点击后应该定位/高亮到下方原始日志文本中的对应位置。
Error文字用Design system的Danger色

### 3. 原始日志文本区（下方）
展示完整的日志文本，格式要求：
- 保留原始行号
- ERROR 行整行用醒目的红色底色/边框标记
- WARNING 行用黄色/橙色文字标记（本次 Mock 数据可以先设为 0 条，但样式规则要预留）
- NOTE 行用普通灰色/次要文字颜色，不需要特别醒目

## Mock 数据要求
- 至少包含 2-3 条 ERROR，用于验证列表可以正常展示多条
- 至少包含 1 条 WARNING（即使真实参考图里是 0 条，Demo 里也要放一条用于验证样式）
- 保留若干条 NOTE（模拟真实场景里 NOTE 数量远多于 ERROR 的情况，比如 Mock 20-30 条即可，不需要真的到 66 条）
- Mock 数据结构建议：
```json
{
  "summary": { "error": 3, "warning": 1, "note": 24 },
  "entries": [
    {
      "level": "ERROR",
      "code": "388-185",
      "description": "期望算术运算符。",
      "logLine": 108,
      "programLine": 84,
      "affectedCode": "! ;"
    },
    // ...更多条目，level 可以是 ERROR / WARNING / NOTE
  ],
  "rawLogText": "完整的原始日志文本，按行组织，用于下方原始文本区渲染"
}
```

## 明确不做的事情（本次范围之外）
- 不需要真实解析 SAS 日志文本生成结构化数据的逻辑，Mock 数据直接写死即可
- 不需要实现"点击表格行跳转到代码编辑器对应行"这个联动（Demo 里可以只做日志区域内部的定位高亮，不用联动到 SAS Code 编辑器）
- 不需要处理 Figure 依赖 T/L 未就绪、外部服务失败等状态——这次只做 Log 结构化展示本身

## 验收标准
- [ ] 顶部有 错误/警告/注意 三个计数器，数字和下方列表条目数一致
- [ ] 计数条旁有上下箭头，点击能在 ERROR 条目之间跳转并高亮
- [ ] 结构化表格只展示 ERROR，字段完整（说明/行/受影响的代码/日志行/程序行）
- [ ] 点击表格某一行，下方原始日志文本区对应位置高亮/滚动定位
- [ ] 原始日志文本区里 ERROR/WARNING/NOTE 三种级别有不同的视觉样式区分
