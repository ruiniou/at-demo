# Component 管理：新增 / 弃用 功能需求

## Background

用户在 Full-scope Review 阶段可能发现两类问题：AI 遗漏了 Shell 里实际存在的 Component（需要新增补充），或者某个 Component 本身用户不需要（需要弃用清理）。这两个操作都发生在 Metadata 面板的 Components 视图（左侧 Component 名单 + 右侧详情的主从布局）里。

---

## 新增 Component

**入口**：Hover 在左侧 Component 列表的 "All" 上时，列表末尾出现 Add 按钮（不常驻显示）。

**流程**：
1. 点击 Add 按钮，展开一个小菜单
2. 菜单内包含：Type（下拉选择）+ 描述（自由文本框）
3. 用户选定 Type 后，文本框内预填对应的 Template 文字；
4. 用户编辑描述后提交
5. 提交后，左侧列表和右侧详情区**同步出现 Skeleton loading**，AI 解析完成后填入新 Component 的实际内容（写回 Metadata 结构化字段）

**备注**：当前先按"小菜单"实现。如果后续发现小菜单空间不够用（比如 Template 内容显示不全），可以考虑改成 Metadata 面板内的一个可返回的二级页面。但这次先按小菜单来做，不做二级页面。

---

## 弃用 / 删除 Component

**适用范围**：所有 Component 都支持（不区分是 AI 生成的还是用户后续手动新增的）。

**入口**：Hover 在左侧列表中的某个具体 Component 上时，出现 **【···】More** 操作入口（不常驻显示）。

**流程**：
1. 点击 More，展开操作菜单，菜单内**弃用、删除两个选项平级并列**
2. **弃用**：可复原，不需要二次确认；弃用状态需要左侧列表和右侧详情区都有视觉区分（不只是列表变灰，详情区也要能看出这是弃用状态）
3. **删除**：不可复原，需要一个拦截 Modal 二次确认，结构如下：
   - **标题**：明确是删除这个 Component（如 "Delete this component?"）
   - **Description**：说明这个操作不可复原，且要跟"弃用"做区分（比如提示"如果只是暂时不需要，可以选择 Deprecate 代替，这个操作可以撤销"）
   - **Key CTA**：主按钮为 "Delete"（警示色，表达破坏性操作），次按钮为 "Cancel"

---

## 明确不需要做的事情

- 不做二级页面（除非小菜单空间实测不够用）
