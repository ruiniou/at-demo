# Antigravity 执行指令：Figure 关联字段组件（Chip 式）

## 目标
在 Atlas 现有 Metadata 面板（Basic 分组）中，改造"关联的 Table/Listing"字段组件。基于**本地 Design System 和组件库**搭建，不新建独立视觉语言——颜色、间距、圆角、字体全部使用现有 token，不硬编码任何具体色值。

## 组件定位
这是 Metadata 字段列表里的一行，展示 Figure 与其关联的 Table/Listing 之间的关系。默认展示态是 **S1（已关联-正常）**，即：绝大多数场景下，Figure 已经有一个明确、有效的关联对象。

## 状态定义（共 5 种）
| 状态 | 定义 | 是否为默认展示态 |
|---|---|---|
| S0 无关联 | 未匹配到关联对象 | 否 |
| S1 已关联-正常 | 关联对象存在，且是最新可用结果 | **是（Demo 默认展示这个状态）** |
| S2 待更新 | 关联对象存在，但内容已变更（被编辑），当前 Figure 结果可能基于旧数据 | 否 |
| S3 已删除 | 关联对象被删除，Figure 失去依赖来源 | 否 |
| S4 依赖报错 | 关联对象本身 Runtime 执行失败 | 否 |

五种状态视觉上需要能明显区分（不只是颜色微调，S3 已删除和 S4 依赖报错尤其要能一眼分辨）。

## 交互一：跳转

- 字段标题（"关联的 Table/Listing"文字本身）右侧放一个独立的跳转icon button(arrow-right-up-line)，作为跳转入口,和文字间距8px。
- 跳转和"编辑"是两个完全分开的动作，不要合并成同一次点击触发。
- 点击后跳转到对应的 Table/Listing 详情页。
- 仅在关联对象**有效存在**时可用（S1、S2、S4 状态下可跳转——S4 时对象还在，只是执行失败，用户可能想去看一眼原因；S0、S3 状态下按钮应禁用/隐藏，因为没有有效的跳转目标）。
- Hover tooltip文案：Go to Dependency

## 交互二：手动编辑（重新指定关联对象）

- 任意状态下都提供编辑入口（嵌在下拉选择框内右侧的图标按钮）。
- 点击后弹出选择器，列出可选的 Table/Listing 供用户重新指定。
- 是否允许手动编辑关联对象，目前仍是产品侧的开放问题（Demo/本组件先按"允许编辑"实现）。

## 手动编辑
1. 用户在关联字段的选择器里，重新选定一个 Table/Listing。
2. Add changes to chat按钮显示。
3. 之后逻辑按Table/Listing现有流程是一样的

## 其他状态的行为约束

- **S2 待更新**：提供"Update"操作，点击后需要 Modal 二次确认（提示"重新执行可能失败"），确认后触发重新执行；执行结果为成功则回到 S1，失败则进入 S4。
- **S3 已删除**：不提供"重新执行"入口（原依赖已不存在，无法凭空重跑），只保留编辑入口引导用户重新指定关联对象。
- **S4 依赖报错**：同样不提供"重新执行"（报错的是依赖对象本身，不是当前 Figure），只保留编辑入口。
- **S0 无关联**：只展示占位文案 + 编辑入口，不展示跳转按钮。

## 设计系统对齐要求
- 所有颜色、圆角、间距、字重必须从本地 Design System token 中取值，不允许写入具体 hex 色值
- 复用组件库里已有的 Chip/Tag、Icon Button、Modal、Dropdown/Select 等基础组件，不重新造轮子
- 状态色的语义需要和现有系统里其他地方的状态色规则保持一致（比如如果系统里"警告"色已经有固定 token，待更新态应该复用它，而不是自定义一个新的橙色）

## 验收标准
- [ ] Metadata 面板 Basic 分组新增关联字段，默认展示 S1 已关联-正常
- [ ] S0-S4 五种状态视觉可清晰区分
- [ ] 跳转按钮独立于编辑按钮，且只在 S1/S2/S4 可用
- [ ] 任意状态都可触发编辑，编辑流程完整包含"发送到 AI Chat → AI Chat 更新代码 → 状态变为 S1"的过渡态，不是编辑完瞬间变更
- [ ] S2 的 Update 操作有 Modal 二次确认
- [ ] S3、S4 都不提供"重新执行"入口，只保留编辑
- [ ] 全部样式基于本地 Design System token，无硬编码色值
