# PM/SME 提问模板库

> 按场景分类。可直接复制到飞书/会议中使用。
> 标注 ⚡ 的是最常用的模板。

---

## 场景1：初次接触新需求 ⚡

**适用时机：** 刚拿到需求文档或口头描述，需要快速对齐

```
我刚看了[需求名称]，想确认几个基本点：

1. **用户角色**：这个功能的主要操作者是谁？（CRA / CRC / 研究者 / 申办方人员？）
   不同角色的操作权限或看到的界面有区别吗？

2. **触发时机**：用户在什么情况下会打开这个功能？
   是主动进入，还是某个事件提醒他们去操作？

3. **完成标准**：用户完成操作后，"成功"的状态是什么样的？
   有没有需要其他人审核/确认的步骤？

4. **MVP边界**：这次交付哪些是必须有的，哪些是nice-to-have？
```

## 场景2：eTMF文件归档类需求 ⚡

**适用时机：** 涉及文件上传、分类、归档到eTMF的功能

```
关于[功能名]的eTMF归档部分，我有几个问题：

1. **文件分类**：文件归档时需要填写哪些属性字段？
   是按TMF Reference Model的层级（区域/国家/Site/研究）来的吗？
   哪些字段是必填，哪些可以留空？

2. **QC流程**：文件上传后有没有质检步骤？
   QC是自动触发还是手动？谁来做QC（上传者自己还是另一个角色）？
   QC不通过时，文件会怎么处理？

3. **查重规则**：系统怎么判断重复文件？是文件名、内容哈希，还是元数据组合？
   发现重复时的预期行为是什么？

4. **合规要求**：这个归档流程有21 CFR Part 11的要求吗？
   具体体现在哪些操作上（比如：需要电子签名、需要操作时间戳、不允许覆盖只允许新建版本）？
```

## 场景3：拍照/扫描归档功能 ⚡

**适用时机：** 设计移动端拍照上传文件的流程

```
关于移动端拍照归档功能：

1. **本地留存**：确认一下，拍照后图片不能保存到手机相册，对吗？
   这个约束是合规要求还是产品策略？后端是怎么处理这个限制的？

2. **拍照后流程**：拍完照片后，下一步是什么？
   用户需要立刻填写文件属性，还是可以先批量拍、之后再分类填写？

3. **失败场景**：如果上传过程中网络中断，照片怎么处理？
   用户需要重新拍还是会有缓存重试机制？

4. **文件格式**：支持哪些格式？除了拍照，支持从手机文件系统选择PDF吗？
   有没有文件大小限制？

5. **批量操作**：用户一次会上传几个文件？
   有没有批量拍照→批量分类的需求？
```

## 场景4：权限与角色类问题

**适用时机：** 当不确定某个功能不同角色的权限边界时

```
关于[功能名]的权限设计，我想确认：

1. 哪些角色可以执行[操作]？（比如：归档、删除、审核、导出）

2. 角色权限是在哪里配置的？是系统级固定的，还是每个项目可以单独配置？

3. 如果用户没有某个权限，预期行为是什么？
   a) 根本看不到这个入口
   b) 看得到但点击后提示无权限
   c) 其他？

4. 有没有"代操作"或"委托"的场景？
   比如CRC代PI操作某些步骤？
```

## 场景5：错误处理与异常场景

**适用时机：** 深入一个功能的边界情况

```
关于[功能]的异常场景，想确认几个：

1. **操作中断**：用户做到一半离开（比如接电话、App退到后台），
   之前的操作会保存吗？下次进来是从头开始还是继续上次进度？

2. **数据错误**：用户提交了错误的数据后能修改吗？
   如果已经进了eTMF系统，修改流程是什么？需要留下修改记录吗？

3. **系统错误**：如果后端返回错误，用户看到什么提示？
   我们现在有错误码的统一规范吗？

4. **超时**：文件上传有超时限制吗？超时后用户需要重新操作还是系统自动重试？
```

## 场景6：确认设计方向是否对齐

**适用时机：** 做了初步方案想在深入之前快速验证方向

```
我做了[功能]的初步方案，想在深入之前先确认方向：

**我的理解是：**
- 用户目标：[XXX]
- 核心流程：[步骤1 → 步骤2 → 步骤3]
- 关键约束：[约束1、约束2]

**不确定的地方：**
- [不确定点1]：我现在的方案是[处理方式]，这样合适吗？
- [不确定点2]：这个步骤是否必要，还是可以简化？

方便的话，能花10分钟帮我看一下方向是否对？不需要看细节。
```

## 通用技巧

**问问题的节奏建议：**
- 初次接触新功能：用"场景1"快速对齐，不要一次问太多
- 开始设计之前：针对最不确定的1-2个点深问（用场景2-5中的模板）
- 方案成型后：用场景6确认方向再深入细节

**飞书消息发送格式建议：**
- 3个以下问题：直接用文字列出
- 3个以上问题：告知"有几个问题想确认，方便的话飞书文档看一下"，然后发文档链接
- 复杂问题：约15-20分钟的对齐会比来回消息更高效

**追问策略：**
如果PM/SME的回答不够清晰，试试：
> "我理解的是[你的理解]，这样对吗？如果不对，能举个例子说明吗？"
