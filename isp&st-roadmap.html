04 / STUDY LOOP MODEL

Study 资产驱动的 Loop 架构

七个核心业务 Loop 覆盖从 Study Intent、CRF 与标准化数据到 TFL Result 的主要资产演进。系统先识别已有资产、版本和批准状态，再按依赖推荐可执行 Loop，并把缺口、降级行为、确认点和版本影响显式呈现。

Study Asset Manifest

Protocol / SAP / CRF / Raw / SDTM / ADaM / Shell / Code / Result

  • AssetVersion、Owner、批准状态、hash
  • 存在 / 缺失 / 冲突 / 过期
  • InputSnapshot 与 TraceLink
→

设计主线｜Loop A

  • SAP → Objective / Endpoint / ARM
  • ARM → TOC / Mock Shell
  • 为 Loop B 提供 TFL Design
  • ARM / TOC / Shell 人工确认
↔

数据主线｜Loop C—G

  • C：CRF/eCRF → aCRF
  • D/E：SDTM Spec → SDTM Output
  • F/G：ADaM Spec → ADaM Output
  • 为分析与 TFL 提供受控数据资产
→

结果主线｜Loop B

  • Shell + Spec/Dataset → SAS/R Code
  • Production Runtime / Log / Result
  • Code 与 Result 在同一 Loop 关闭
  • Mapping / Code / Run / Result 确认
所有 Loop 的统一版本行为：每次运行固化 InputSnapshot；输入版本变化后先进行 Impact Analysis，只从最小安全锚点重跑受影响对象，生成新的 Output Version，保留历史输出、人工锁定内容、ReviewDecision、Run / Log 与端到端 TraceLink。原 Loop M 因此不再单列。

05 / TECHNOLOGY BASELINE

Atlas 信息反映的主要技术与产品化方向

这里只描述已能从对话、功能清单和目录资产中确认的能力技术，不臆测具体前后端框架、向量数据库或云厂商。

Agent / Node 工作流

已有方向包括 AI 生成链路拆点、节点级上下文组织、步骤运行控制、递归规避、失败定位与重跑。Evaluation Agent 不是单轮 Judge，而是加载额外信息并执行多步验证。

产品化：统一为 LoopDefinition → StepRun → Gate → Artifact 的状态机；模型、Prompt、KB和工具版本随 Run 固化。

Shell 语义结构化

Atlas 输出 JSON 已包含 Table / Figure / Listing 类型、row/column/cell、层级、对齐、颜色、页信息、annotation 和 mosaic metadata，说明 Shell 已被转为可查询的 canonical 对象。

产品化：保留平台中立 Schema；企业字段进入扩展命名空间，避免产品核心依赖专属页面结构。

多路 Reference 召回

功能清单明确要求 Table / Listing / Figure 特征抽取、Reference锚定、全局Reference、上下文构建与生成链路使用。仅依赖一个大向量检索分数会削弱可解释性与召回稳定性。

产品化：结构化过滤 + 特征召回 + 语义召回 + rerank + 运行验证，所有结果带适用范围与版本。

SAS 代码生成与 Copilot

现有能力围绕 Macro参数、Block、Group、Page-by、Filter、Program name、Suffix、数据前/后处理、Uncovered Code、代码编辑、局部Regenerate和Diff展开。

产品化：先生成 Program Design IR，再组装批准 Macro / Template / Reference；人工锁定代码块不被局部重跑覆盖。

Runtime 与反馈闭环

已有规划包括编译检查、服务接入、Dummy Data、日志解析与回传、执行结果用于错误归因，以及 Review 节点。Runtime把代码生成转化为可验证结果。

产品化：SAS Runtime Adapter 在 v1.0 先行；v1.3（2027.03—04）引入 R Adapter，重跑创建新 Attempt，不覆盖历史 Run。

R / Pharmaverse 路线

GAutoTLF 方案以 R Shiny、R Template、Pharmaverse/rtables、Shell Processor、本地执行、自动修复和 Human Review 为核心。它适合作为 R Programming Engine，不适合作为统一主产品入口。

产品化：复用函数、模板、包依赖与Runtime经验；UI、对象、编排、资产和审计统一上收至 iSP。

Study / Event / 版本治理

Atlas 已暴露 Event、Study级参数、输入变更、多人编辑、代码版本、Metadata↔Code一致性、Review关键信息和审计追踪等产品需求。

产品化：Study是资源边界，Event是业务意图，InputSnapshot是可复现输入，所有批准对象追加版本。

安全与部署底线

Atlas二期清单覆盖 SSO、权限、审计、加密、净化层、TLS/mTLS、API安全与限流、数据保留、CI/CD安全和部署。

产品化：这些不是“后补非功能”；在 v1.0 受控试点前必须完成最小可验证底线。

质量工程

目录与计划同时包含 validation log、自动 dry run、table 对比、评估 Agent、错误归因、SIT/UAT 与客户验证样本。AI准确率必须按场景、输入完整度和复杂度分层。

产品化：以 first-pass runnable、业务可用、最终运行成功、人工修改量和追溯完整率组成指标组合，不用单一“准确率”。

推荐的检索—生成—验证链

1. 强过滤企业 / Study / TFL类型 / 语言 / 版本 / 有效期
2. 特征召回Analysis signature、Dataset、Macro参数、Shell结构
3. 语义召回SAP语义、标题、脚注、规则与历史问题
4. Rerank适用度、业务优先级、证据、批准状态
5. 执行验证静态检查、Runtime、Log、Result与人工Review
为什么不做“纯向量检索 + Top-K”：对 Reference Program 来说，很多关键差异藏在少数结构化维度（TFL类型、分析方法、Population、Dataset、Macro、输出形态）。先做强过滤和特征召回，再进行语义检索与重排，可以减轻高维距离集中导致的排序不稳定，也更容易解释和验证。

09 / DATA SECURITY & AI BOUNDARY

数据集安全风险与 AI 使用边界

随着 Loop C—G 开始接触 Raw、SDTM 与 ADaM 数据集，安全控制需要从文件管理升级为覆盖输入、检索、生成、运行、输出和审计的全链治理。AI 只承担建议、生成与辅助验证，不替代有资质人员的批准和业务判断。

数据分级与最小化不足

Raw Data 可能包含直接或间接身份信息。接入前执行数据分级、去标识化或假名化，只向当前 Loop 提供完成任务所需的最小字段和最小记录范围；测试优先使用合成或脱敏数据。

跨 Study / 跨企业数据串用

Study 与企业命名空间必须作为强隔离边界。资产、向量索引、缓存、运行目录和结果均继承租户与 Study 权限；默认拒绝跨域检索，采用最小权限、职责分离及访问到期机制。

运行环境与结果泄露

SAS / R 代码在受控沙箱中执行，限制外部网络、文件系统和未批准包；传输与静态存储加密。Log、错误栈、Preview 和导出文件需进行敏感值遮蔽，临时数据按策略自动清理。

外部模型的数据使用风险

敏感数据默认不进入公共模型或未批准服务。仅允许白名单模型端点，并明确不用于模型训练、受控保留期限和数据驻留要求；优先发送结构化 Metadata、必要片段或脱敏上下文，而不是完整数据集。

AI Touch 生产级 Raw / SDTM / ADaM 数据

行级生产数据进入模型上下文可能造成敏感信息泄露、缓存或日志残留；AI 直接生成或修改 Dataset 还可能引入静默误改、版本污染和不可复现结果。默认仅向 AI 提供 Schema、Metadata、统计摘要或脱敏样本；确需访问时采用临时、只读、最小字段授权。AI 只生成 Mapping、转换建议或代码，不直接写入生产数据集；实际转换必须在受控 Runtime 中确定性执行，并经过 Dataset Diff、规则校验和人工批准。

AI 越权作出业务结论

AI 可生成 TOC、Shell、Spec、Mapping、代码和问题建议，但不得自行批准 Spec / Dataset / TFL，不得替代统计师确认结果正确性，不得自动执行申报发布。关键 Gate 必须由授权人员确认。

Prompt / 知识库注入与不可追溯

上传文档、Reference Program 和检索内容均视为不可信输入，进行来源校验、内容净化与工具权限限制。每个输出固化 Model、Prompt、KB、InputSnapshot、Code、Run 与 ReviewDecision 版本，并支持停用与回滚。

明确红线：不上传未脱敏的直接身份信息；默认不向模型暴露行级生产 Raw / SDTM / ADaM 数据；不允许 AI 直接写入或覆盖生产数据集；不允许跨企业或跨 Study 默认召回；不允许生成代码在无隔离环境中执行；不允许 AI 绕过 Review Gate 自动批准、发布或申报。任何红线触发时，Loop 必须阻断并生成可审计事件。
